Apa yang terbuka di tier ini

Pratinjau gate untuk tier terpilih — memakai fungsi yang sudah ada di lib/access.ts.

Jangan lupa: menambah tier menyentuh satu sumber kebenaran. lib/access.ts memakai tipe AccessTier = "free" | "starter" | "pro". Di getAccessTier(), PRO/PRO_YEARLY memetakan ke "pro" dan STARTER ke "starter" — semua nilai lain jatuh ke return "free". Jadi kalau "ENTERPRISE" tidak ditangani di sana, user Enterprise akan diperlakukan sebagai Free dan kehilangan seluruh akses berbayar — bukan sekadar gate tambahannya yang mati.

Kenapa Enterprise, bukan tier baru di bawah Pro

Menaruh tier baru di bawah Pro berarti menurunkan Pro — semua user Pro yang sudah ada kehilangan fitur diam-diam. Enterprise di atas Pro tidak memutus apa pun, dan prdLimit: -1 milik Pro tetap utuh.

Yang berubah di kode
// lib/plans.ts
export type PlanCode =
  | "FREE" | "STARTER"
  | "PRO" | "ENTERPRISE";

// lib/access.ts
export type AccessTier =
  | "free" | "starter"
  | "pro" | "enterprise";
Gate baru untuk editor tema
// library tema = pembeda Pro vs Enterprise
export function canSaveThemes(sub){
  return getAccessTier(sub)
    === "enterprise";
}

// prototype = pembeda Starter vs Pro
export function canUsePrototype(sub){
  return getAccessTier(sub)
    === "pro"
    || getAccessTier(sub)
    === "enterprise";
}
Perhatikan urutan cek

canFork() di access.ts:56 sekarang getAccessTier(sub) === "pro". Setelah ada Enterprise, cek ini harus jadi tier === "pro" || tier === "enterprise" — kalau tidak, Enterprise kehilangan Fork. Ini satu-satunya gate di file itu yang membandingkan tier secara literal; perbaikannya harus di titik panggil ini, bukan di getAccessTier().

Dua cara gagal, dua-duanya senyap

(1) Fallthrough tier. Lupa menangani ENTERPRISE di getAccessTier() → jatuh ke "free" → user kehilangan semua akses berbayar. Ini merambat otomatis ke gate yang murni memakai isPaid() — canAccessVault, canExport, canUseCli, canGenerateAdvanced, canDownloadMarkdown — dan juga ke canGeneratePrd (yang memakai isPaid() sebagai syarat pertama, lalu cek kuota). Perbaikan di satu fungsi menyembuhkan semuanya.

(2) Perbandingan tier literal. Gate yang menulis === "pro" tidak ikut membaik walau mode (1) sudah dibereskan. Saat ini hanya canFork() yang begitu — jadi harus ditangani terpisah. Kalau nanti ada gate serupa, pola ini akan terulang.

Masalah grid 4 kartu

pricing-plans.tsx memakai lg:grid-cols-3. Dengan 4 tier hasilnya 3+1 — jelek. Harus jadi lg:grid-cols-4 (atau xhtml:grid-cols-2 xl:grid-cols-4) dan padding kartu dikurangi, karena 4 kolom di lebar yang sama membuat teks sempit.
